# Application feedback (20260914120000)

## Affected tables

- `feedback` (new): one row per "Give us feedback" submission from any screen,
  signed in or anonymous. It is the system of record for feedback.
  - `submitter_type` is `AUTHENTICATED` when a valid session identified the
    user, otherwise `ANONYMOUS` with every identity column `NULL`.
  - `user_*`, `tenant_*`, `facility_*`, and `subscription_*` columns are
    snapshots taken at submission. `user_id`, `tenant_id`, and `facility_id`
    are nullable foreign keys with `ON DELETE SET NULL`, so removing an account
    never removes its feedback.
  - `route_path` and `page_url` are stored after the backend strips tokens,
    codes, passwords, email addresses, and phone numbers from query strings
    (including queries inside a `#/` fragment).
  - "Clear feedback" deletes the selected rows permanently. `deleted_at` and
    `deleted_by_user_id` remain for rows soft-deleted by the first release;
    listings, counts, and exports still skip rows where `deleted_at` is set.
- No existing table is altered.

## Identifiers

`human_friendly_id` uses prefix `FBK` on one platform-wide counter
(`global:model:feedback:prefix:FBK`), so ids never repeat across tenants in an
export.

## Deployment

1. Apply migration `20260914120000_feedback` (`npm run prisma:migrate:deploy`).
2. Deploy application code. `POST /api/v1/feedback` needs the table.
3. Verify:
   - `POST /api/v1/feedback` without a token returns 201 with
     `"submitter_type": "ANONYMOUS"`; with a session it returns `"AUTHENTICATED"`.
   - `GET /api/v1/feedback/export` returns `HOSSPI-FEEDBACK-DDMMYYYY-HHmmss.xlsx`
     for a platform owner or platform admin, and 403 for a tenant admin.
   - `DELETE /api/v1/feedback` with `{ "confirm": true, "human_friendly_ids": [...] }`
     removes those rows permanently.

## Recovery

Forward-only. Deleting feedback from the app is permanent, so download it first
when a copy may be needed. Removing the feature needs no data migration: add
`rollback_20260914120000_feedback` dropping the table if required. Dropping it
discards every submission.
